# beets-rs

A Rust port of the core of [beets](https://github.com/beetbox/beets), the music
library manager: import with MusicBrainz autotagging, a SQLite library, beets'
query language and path-format templates.

The binary is `beet`, and the query, template and config syntax follow beets,
so the [beets docs](https://beets.readthedocs.io/) mostly apply. The library
database has beets 2.14's schema, but config and library live in
`~/.config/beets-rs/` (override with `$BEETSRSDIR`) so a real beets
`library.db` is never touched; `beet migrate-beets` copies one in (see below).

```sh
cargo build --release
beet import ~/Downloads/SomeAlbum        # interactive autotagging
beet import -q -m ~/incoming             # quiet: apply strong matches, skip the rest
beet import -i ~/Downloads               # incremental: skip folders imported before
beet ls artist:radiohead year:2000..2009 year-
beet ls -a -f '$albumartist - $album ($year)'
beet modify -a 'in rainbows' genre=Alternative
beet modify nude 'title=$title (live)' mood=calm   # values are templates; unknown fields become flexible attributes
beet mv -e -d /mnt/usb artist:radiohead            # export copies with library path formats (library unchanged)
beet update -F title -F artist                      # re-read changed tags (only these fields), drop deleted files
```

## What's implemented

| Area | Status |
|---|---|
| `import` | album and singleton (`-s`) modes; copy/move/in place (`-c/-C/-m/-M`); `link` (symlink), `hardlink`, `reflink: yes/no/auto` (auto falls back to copying), with beets' precedence (move, link, hardlink, reflink, then copy); `delete` (remove originals after copying); `ignore` globs and `ignore_hidden` when walking import directories; `-q` with `--quiet-fallback skip/asis`, `-t`/`timid`, `-a/-A`, `-w/-W`, `-S <mbid>`; `--pretend` (list files only); `--flat`; `--set field=value` / `set_fields` (templates); `-l/--log` / `log` (beets' log format); `none_rec_action`; `default_action` (apply/skip/asis/none: the confirm prompt's default); `detail`; directory grouping as beets' `albums_in_dir` (multi-disc albums collapsed from nested disc folders such as `CD1`/`cd 3 - bonus` or sibling folders such as `Album Disc 1`/`Album (CD 2)`, by beets' disc/cd/cassette/digital media/vinyl markers; the import state keys a collapsed album by its first path); `-g`/`group_albums` (split folders into albums by tags); duplicate detection for albums and singletons by `duplicate_keys` (`album`, `item`; exact field matches, flexible attributes too), with `duplicate_action` skip/merge/remove/keep/upgrade/ask (Upgrade imports only tracks that are new or have a higher bitrate than the old copy, adding them to the surviving old album), `duplicate_verbose_prompt`; `bell`; `singleton_album_disambig`; reimporting (by path or `-L/--library` query: rows replaced, files moved rather than copied inside the library, `added`/flexible attributes/art kept); `--from-scratch`; `overwrite_null` (`album`/`track` lists: values a match lacks keep the item's unless listed, by the match's or the item's field name); incremental imports (`-i`/`-I`, `-R`/`-r` for `incremental_skip_later`); resuming interrupted imports (`resume: ask/yes/no`, `-p/--resume`, `-P/--noresume`), with state in `statefile` (JSON); "Rescan directory" (R) at the album prompt, as beets 2.14: offered for albums read from a directory (not after "Group albums" or `-g`, nor for merged or `-L` imports), re-walks the album's directories (their parent, filtered back, for sibling disc directories) and runs each album found through the prompt again; aborting (B) stops silently and the end of input is beets' "stdin stream ended while input required" error; `threaded` (default yes: two threads read and look up the next few albums or tracks, at most 4 including the current one, while you answer the prompt and the files are imported; prompts, duplicate checks, file operations, database writes and plugins stay in order on the main thread, so output and state are as with `threaded: no`) |
| Autotagger | MusicBrainz as beets 2.14's `musicbrainz` plugin: release search by lower-cased album and artist (the Various Artists id for likely-VA albums) plus `musicbrainz.extra_tags`, recording search then lookup by id, `search_limit`, beets' includes, `host`/`https`/`ratelimit` (musicbrainz.org always https at 1 req/s, shared by the threaded importer's lookahead), pseudo-releases merged with their actual release, releases over 500 tracks browsed for their relations; every field beets reads from the JSON (artist credits with join phrases and the `artists`/`artists_sort`/`artists_credit`/`artists_ids` lists, album types incl. secondary, status, release group title, script, language, ASIN, barcode, works with composers/lyricists, arrangers, remixers, ISRCs, `track_alt`, disc titles, `musicbrainz.genres`/`genres_tag`, `external_ids`, VA as `va_name`), applied as beets' `merge_with_album`/`item_data` (`artist_credit`, `per_disc_numbering`, `original_date`, `overwrite_null`, list fields kept in sync, the album's flexible fields inherited by its items), checked field by field against reference beets; a port of beets' `distance.py` and `match.py`, checked against reference beets' numbers: `string_dist`, weighted penalties in insertion order (`match.distance_weights`, all of beets 2.14's keys incl. `data_source` (`musicbrainz.data_source_mismatch_penalty`) and `medium`), the album's most common tags (beets' `Likelies`), `track_length_grace`/`track_length_max`, per-disc or per-release track numbers, `preferred` media/countries/original year, the items' own release looked up first (returned alone when it's a strong match); `match.required` (drop candidates missing a field) and `match.ignored` (drop candidates with a penalty); `ignored_media`, `ignore_data_tracks`, `ignore_video_tracks` (pregap tracks kept, as beets); Hungarian item↔track assignment; `import.languages` / `ignored_alias_types` / `musicbrainz.aliases_as_credits` (preferred MusicBrainz aliases for artist names, sort names and titles); strong/medium/low recommendation with `max_rec` caps (album and track penalties); candidate disambiguation by `match.album_disambig_fields` / `singleton_disambig_fields`, formatted as beets 2.14 does (a missing value shows as `None`) |
| Prompts | Apply, More candidates, Skip, Use as-is, as Tracks, Group albums, Enter search, enter Id, aBort (singletons the same without as Tracks/Group albums); candidate list; picking a candidate, or a medium/low top match, shows the change and asks to confirm (More candidates returns to the list; strong matches apply without asking unless timid); per-track change display |
| Queries | as beets (`dbcore` query/queryparse/sort): terms over the default fields; `field:` substring; `=`/`=~` exact (case-sensitive / not) and `:` regex prefixes, with or without a field (regexes are Python-style via fancy-regex, case-sensitive, NFC-normalized); `\:` escapes a colon; `-`/`^` negation of any part; `,` (also at the end of a term) for OR; numeric ranges with `..` on typed fields (`year:..1999`, `bitrate:128000..`, `length:..4:30`); dates with year/month/day/hour/minute/second precision (`T`, `t` or space before the time), open and back-to-front ranges, and relative dates (`-1w..`, `-6w..-4w`, `+4d`: d/w/m/y = 1/7/30/365 days); booleans (`comp:yes`); `singleton:`; `path:` (absolute, or relative to the library directory; directory or file; case sensitivity from the filesystem) and implicit path queries (a term with a `/` that exists); item queries reach album fields and album flexible attributes, album queries match on their items' fields; sorts `field+`/`field-` (several; flexible and computed fields; `artist`/`albumartist` via their `_sort` fields), `sort_item`, `sort_album`, `sort_case_insensitive`; invalid queries give beets' `invalid query: '...': ...` message. Fixed-field queries and sorts run in SQLite (with the items↔albums join); flexible/computed parts are matched in memory |
| Templates | as beets (`functemplate`): `$f`, `${f}` (anything up to `}`), `$$ $% $} $,` escapes, unknown symbols/functions and malformed calls left verbatim, a top-level `}` ends the template; functions `%lower %upper %capitalize %title` (Python `capitalize`/`capwords`) `%left %right` (Python slicing, negative counts) `%if` (int/`false`/empty) `%ifdef` `%asciify` `%time` `%first`, `%aunique{keys,disambiguators,brackets}`, `%sunique{...}` (singletons; `sunique:` config) and `%tunique{...}` (tracks of one album; `tunique:` config), with beets' fallback numbers, empty-disambiguator dropping and sanitized comparison; wrong argument counts or bad numbers render beets' `<error>` text. `%asciify` and `asciify_paths` follow Python's unidecode for Latin, Greek, Cyrillic, CJK (ideographs end in a space: `日本` → `Ri Ben `) and kana (rarer symbols and scripts can differ: unidecode's GPL tables aren't copied). Fields formatted as beets: `$bitrate` `320kbps`, `$samplerate` `44kHz`, `$length` M:SS, padded `$track`/`$disc`/`$year`…, `$filesize`, `$singleton`, `$id`, `$album_id` (empty for singletons), `$has_cover_art`; album fields and flexible attributes in item templates (album values first in paths), albums' `$path` and `$albumtotal`; `$artist`/`$albumartist` fall back to each other |
| Paths | `paths:` in config order, first matching query wins (`comp` and `singleton` are the queries `comp:true`/`singleton:true`), else `default`; values can't add separators (`path_sep_replace`, `drive_sep_replace`); `asciify_paths` (unidecode-style, after templating); `replace:` (Python regexes and `\1` replacements, applied per component in order; a user `replace:` replaces the defaults, as in beets); `empty_component_replace`; beets' `legalize_path` (lowercased extension, each component truncated to `max_filename_length` bytes (else the filesystem's limit, at most 200) keeping the extension, re-sanitized, falling back to the default replacements with a warning); `art_filename` (template for album art names, used by fetchart, `mv` and `extractart -a`); unique-path suffixes; empty-dir pruning (directories holding only `clutter` files count as empty) |
| Commands | `import` (`imp`, `im`), `list` (`ls`), `modify` (`mod`), `remove` (`rm`), `move` (`mv`), `update` (`upd`, `up`), `write`, `stats` (beets' `show_stats`: estimated or `-e/--exact` size and time, `-l/--limit`), `fields` (as beets: sorted fixed and computed fields per model, then the library's flexible attributes), `config`, `version`, `help [COMMAND]` (`?`), with beets' aliases; no command shows the help, and an unknown one gives beets' `unknown command 'x'` error |
| `modify` | as beets: `field=value` (values are templates, parsed by field type with beets' leniency: unparsable numbers become 0), `field!` (drops a flexible attribute, resets a fixed field), query terms otherwise (anything with `:` before the `=`); `-a` with album changes inherited by the items (fixed fields and flexible attributes, set or deleted; `-I/--noinherit` to keep them on the album), `-m/-M` (default: `import.move` or `import.copy`), `-w/-W` (default `import.write`), `-f/--format`, `-y`, `-l/--limit`; beets' change listing ("Modifying N items.", `field: old -> new` with difflib-style highlighting) and the "Really modify, move and write tags? (Yes/no/select)" prompt with per-object selection; `update` shows changes the same way |
| `update` | as beets: re-reads files whose mtime is newer than the stored one, shows changes the same way, and stores them; `-a`, `-m/-M` (default: `import.move` or `import.copy`; only files inside the library move), `-p/--pretend`, `-F/--field` (repeatable: only these fields), `-e/--exclude-field` (repeatable), `-f/--format`, `-l/--limit`; missing files are listed as "deleted" and removed (an emptied album goes too, with its art); albums take their fields from their first item again, and pass changes on to their items; asks before going on when the library directory is missing |
| `write` | as beets: writes tags only to files whose tags differ from the database, listing the differences (`field: file -> db`); `-p/--pretend`, `-f/--force` (write every file), `-l/--limit`; missing files are reported and skipped |
| `remove` | as beets: lists the items (with `-d`: `$path - $title`; with `-a`: grouped by album) and asks "Really remove N items [and M albums] from the library? (Yes/no/select)" or "Really DELETE N files [and M albums]? (Yes/no/select)", with per-object selection; `-a`, `-d/--delete` (deletes the files and album art, pruning emptied directories), `-f/--force`, `-l/--limit`; an album left empty is removed |
| `config` | as beets: without options, the configuration from the user's file, its includes, `-c` files and command-line options, plus the defaults of enabled plugins (or "Empty configuration"); `-d/--defaults` (everything, defaults included), `-c/--clear` (don't redact; by default enabled plugins' key/password settings show as `REDACTED`: fetchart `google_key`, `google_engine`, `fanarttv_key`, `lastfm_key`; lyrics `translate.api_key`, `google_API_key`, `google_engine_ID`, `genius_api_key`), `-p/--paths` (the files read, highest priority first; the user's `config.yaml` is listed first if it doesn't exist), `-e/--edit` (opens the first `-c` file or the user config, created if missing, with the `editor` option, `$VISUAL`, `$EDITOR`, or `xdg-open`/`open`; works even when the config is broken) |
| Config files | `config.yaml` in `$BEETSRSDIR` or `~/.config/beets-rs`; `include:` (list of files relative to that directory, each over the last; an unreadable one stops the includes with beets' "configuration `import` failed" message); `-c` files over those; relative paths in values (e.g. `library`) resolve against the config directory; unreadable files give "configuration error: FILE could not be read: ..." |
| UI | beets' `ui:` options: `color` (off also with `NO_COLOR`; like beets, no terminal check), `colors` (the 14 names `text_success`, `text_warning`, `text_error`, `text_highlight`, `text_highlight_minor`, `action_default`, `action`, `text_faint`, `import_path`, `import_path_items`, `action_description`, `changed`, `text_diff_added`, `text_diff_removed`, each a list of styles/colours such as `[bold, green]` or a legacy name like `darkred`; anything else is a configuration error), `terminal_width` (when the terminal size is unknown), `length_diff_thresh`, `import.indentation` (`match_header`, `match_details`, `match_tracklist`), `import.layout` (`column` or `newline`); beets' prompts ("➜ [A]pply, More candidates, ...?", "# selection (default 1)", "Enter one of ...") |
| Import display | as beets: the task's paths (one per line: the parent and each disc directory for a merged multi-disc album) and "(N items)", "Finding tags for album \"Artist - Album\"." with the candidate list (similarity, "≠ penalties", disambiguation), and for the chosen match "Match (95.3%):", artist and album lines ("* Artist: X" or "≠ Album: old -> new"), disc headers, changed tracks in two columns (wrapped or on new lines when long; all tracks with `import.detail`/`--detail`), missing and unmatched tracks; singletons likewise ("Finding tags for track ...") |
| Global options | before the command, as in beets: `-l/--library`, `-d/--directory`, `-c/--config FILE` (repeatable; each file goes over the user config and the files before it, as in beets), `-v/--verbose` (repeatable: `-v` logs config/library paths, plugin loading, MusicBrainz searches and lookups, duplicates found; `-vv` also each MusicBrainz request), `-p/--plugins LIST` and `-P/--disable-plugins LIST` (comma-separated; also the `disabled_plugins` config key), `-h/--help`, `--version` |
| Tags | MP3, FLAC, M4A/ALAC, Ogg Vorbis/Opus/Speex, WavPack, APE, Musepack, AIFF, WAV, through a port of MediaFile's field table on lofty's per-format tags: every field beets reads and writes (`title`, `artist(s)`, `album`, `albumartist(s)`, the `_sort`/`_credit` variants and their lists, `genres`, `composers`, `composer_sort`, `lyricists`, `arrangers` (ID3 `TIPL`), `remixers`, `grouping`, `subtitle`, track/disc numbers and totals, dates and original dates, `comments`, `lyrics`, `bpm`, `comp`, `label`, `catalognum`, `barcode`, `isrc`, `asin`, `script`, `language`, `country`, `albumstatus`, `albumtype(s)`, `media`, `albumdisambig`, `disctitle`, `encoder`, `initial_key`, every `mb_*` id incl. the artist id lists, AcoustID, ReplayGain gain/peak (incl. iTunes Sound Check `iTunNORM`) and R128 gains) under MediaFile's frames, `TXXX` descriptions, MP4 atoms and `----:com.apple.iTunes:` names, Vorbis and APEv2 keys, alternative and read-only keys included (`ALBUM ARTIST`, `UPC`, `CATALOGID`, ...); reading follows MediaFile's rules (first style with a value wins, `YEAR` as the date's fallback, ID3v1 merged in, ID3v2.3 lists split on `/` where MediaFile does, ffmpeg's `TXXX:TCMP` ignored, ID3 genres through mutagen's `TCON.genres`: `80` or `(17)Rock` are ID3v1 genre names, with mutagen's genre table) and writing writes every writable style in MediaFile's order (where beets writes an empty value or 0, beets-rs removes the tag: MediaFile reads both the same); `id3v23: yes` writes MP3s as ID3v2.3 (lists joined with `/`, genres as names, dates as `TYER`/`TDAT`/`TORY`, as mutagen does); `length` and `bitrate` exactly as beets stores them (mutagen's per-format values, read from the headers: MP3 Xing/Info/LAME/VBRI or the stream size, FLAC/WavPack/APE sample counts, MP4 `mdhd` and sample-entry bitrates, Ogg Vorbis/Opus granule positions, WAV/AIFF; MediaFile's file-size estimate where the format has no bitrate), AAC `bitdepth` from the sample entry; MP3 `bitrate_mode` (CBR/VBR/ABR), `encoder_info` (`LAME 3.100.0+`, `FhG`) and `encoder_settings` (mutagen's guess, e.g. `-V 2`, `--preset 128`) from the Xing/Info, LAME and VBRI headers as mutagen reads them (empty for other formats, as in beets); WAV's format is `WAVE`; as in beets, changing a tag field in the library resets the item's `mtime` until the file is written, so `update` re-reads it (an as-is import that fills in `albumartist`/`comp` without writing counts too). Not yet: ASF/WMA (lofty has no ASF support) |
| Multi-valued fields | beets 2.x's lists (`genres`, `artists`, `albumartists`, `composers`, `lyricists`, `arrangers`, `remixers`, `mb_artistids`, `albumtypes`, ...): stored joined with beets' `\␀` delimiter (`albumtypes` with `; `), shown and parsed with `; `; queries in SQL see the joined string, in-memory matches any value; `modify field=a; b`, `field+=c` (adds missing values), `field-=a`; changes listed as beets' `+ value`/`- value` lines; the legacy single-valued names (`genre`, `composer`, `lyricist`, `arranger`, `remixer`) in queries and `modify` mean the lists, with beets' deprecation warning; an existing beets-rs library's `genre`/`composer` columns are migrated once (split on `; `, `, `, ` / `, as beets does), after a backup to `<library>-before-<table>-<migration>.bak` with beets' "Created database backup at: ..." message (`create_backup_before_migrations`, default on; unlike beets, only made when a migration changes data, so a new library gets none); autotagged single values (`artist`, `mb_artistid`, `albumtype`, ...) head their lists. Also beets' nullable `rg_*`/`r128_*` floats and the normalized `initial_key` (`Ebm` is `D#m`) |
| Library database | beets 2.14's `library.db` format, statement for statement: the `items`/`albums` tables with beets' columns and types (sorted by name), `item_attributes`/`album_attributes` (flexible attributes, `data_source` among them), the `idx_item_album_id` index and the `migrations` table; paths (`path`, `artpath`) stored as blobs relative to `directory` when inside it (absolute otherwise), a singleton's `album_id` NULL, `added`/`mtime` floats. beets' data migrations run once each on opening (multi-valued fields, `relative_path`, `remove_inherited_artpath`, lyrics metadata and instrumental markers into flexible attributes; beets' `langdetect` language guess isn't ported, and an instrumental marker is left for the instrumental migration rather than blanked first). A library made by an older beets-rs is rebuilt in this layout once (backed up to `<library>-before-beets_layout.bak`). Unlike beets, the database uses SQLite's WAL journal |
| `migrate-beets` | `beet migrate-beets [--beets-config PATH] [-d DIR] [-f] LIBRARY_DB` copies a beets library's items, albums and flexible attributes into the beets-rs library, ids kept (so album links hold). The beets database is opened read-only and immutable (SQLite `mode=ro&immutable=1`): never written, no journal or lock file made beside it; refused while a `-journal`/`-wal` file shows beets may be writing. beets stores paths relative to its `directory`: give it with `-d/--directory DIR` or `--beets-config PATH` (its `directory:`, `~` expanded, relative to the config's folder, beets' `~/Music` if unset; the file is only read). Paths are then stored relative to beets-rs' own `directory` when inside it. Refused when the beets-rs library already has items or albums, unless `-f/--force`, which replaces them after a backup to `<library>-before-migrate-beets.bak` (no merging). Columns beets keeps that beets-rs doesn't (such as an old beets' `genre`) are kept too, and beets' migrations that the source library hadn't had yet run on the copy. Afterwards it warns if items' files don't exist (a wrong directory) |
| Release preferences | `match.preferred.countries` / `media` (regex lists, earlier = better) and `original_year`, as in beets |
| Plugins | enabled with `plugins:` (default `[musicbrainz]`, as beets: the autotagger looks up MusicBrainz only while `musicbrainz` is enabled); import hooks + subcommands. **fetchart** (folder image, then Cover Art Archive; `beet fetchart [-f]`), **lyrics** (LRCLIB, plain or synced; `beet lyrics [-p] [-f]`), **embedart** (embeds the album art on import, always after fetchart; `beet embedart [-f IMAGE] [-y]`, `beet extractart [-o PATH] [-a] [-n NAME]`, `beet clearart [-y]`; options `ifempty`, `remove_art_file`) |
| `move` | as beets: consolidates into the library directory, or `-d/--dest DIR`; `-c/--copy` (copy and point the library at the copies), `-e/--export` (copy, library unchanged), `-p/--pretend` (beets' `Source -> Destination` listing, two lines per file when it doesn't fit), `-t/--timid` ("Really move? (Yes/no/select)"), `-a`, `-l/--limit`; "Moving N items (M already in place)."; taken destinations get beets' `.1`, `.2` suffixes; missing files are skipped; emptied library directories are pruned (`clutter` ignored) |
| Album art | `artpath` follows the album on `mv`/`modify`/`update` (copied, and the copy recorded, with `mv -c`; copied into the export with `mv -e -a`, as beets, but not with item exports), and is deleted by `rm -d` |

## Example config

```yaml
directory: ~/Music
plugins: fetchart embedart lyrics
match:
    preferred:
        countries: ['GB|UK', US]
        media: [CD, Digital Media|File]
        original_year: yes
fetchart:
    maxwidth: 1200      # use Cover Art Archive's 1200px thumbnail
lyrics:
    synced: no
```

## Differential testing

`tools/diffbeets/diffbeets.py` builds the same library with reference beets
and with beets-rs (generated audio, same config) and compares `ls`, `ls -a`,
`-f` templates and `mv -p` destinations over ~1000 cases taken from beets' own
tests, runs the same cases on a beets-rs library made with `migrate-beets` from
reference beets' library, then has each tool write its tags and compares the
files as MediaFile reads them (and both tools' reading of the files beets
wrote); known,
deliberate differences are listed with their reasons in
`tools/diffbeets/cases.py`. See `tools/diffbeets/README.md`.

## Layout

`model` (typed fields + flex attrs) · `library` (SQLite, beets' schema and migrations) · `migrate` (`migrate-beets`) · `query` · `template` ·
`paths` · `duplicates` (duplicate keys, Upgrade, prompt summaries) · `fileops` (copy/move/link/reflink, pruning, ignore globs) · `media` (reading/writing items' files, art) · `mediafile` (port of MediaFile's tag mapping) · `props` (mutagen's length and bitrate) · `mb` (MusicBrainz) · `autotag` · `importer` ·
`commands` · `diff` (change highlighting) · `logging` (`-v`) · `state` (import resume/history) · `ui` · `plugins/` (`fetchart`, `embedart`, `lyrics`).
