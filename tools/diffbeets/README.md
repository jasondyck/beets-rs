# diffbeets: beets-rs against reference beets

```sh
~/.cache/beets-reference/venv/bin/python tools/diffbeets/diffbeets.py
```

It builds `target/release/beet` (skip with `--no-build`), then in a fresh temp
dir (under `$TMPDIR`, or `--workdir DIR`):

1. generates a corpus of 1-second audio files with ffmpeg (`src/`): unicode,
   `½`, slashes, quotes, `$ % { } ,` in titles, empty fields, a multi-disc
   album in `CD1`/`CD2`, a VA album, same album name by different artists and
   years, long names, leading dots, singletons, and one track per format
   and codec with odd lengths (MP3 CBR/VBR/no Xing header, FLAC, AAC, ALAC,
   Ogg Vorbis, Opus, WavPack, AIFF, WAV) for exact `length`/`bitrate`;
2. writes the same `config.yaml` (and the extra configs used with `-c`) to
   `ref/` and `rs/`, differing only in `directory:` (`ref/lib`, `rs/lib`);
3. imports every directory as-is (`import -A -q`, copying) and applies the
   same `modify` commands with each tool: reference beets via
   `~/.cache/beets-reference/beet` with `BEETSDIR=<tmp>/ref`, beets-rs with
   `BEETSRSDIR=<tmp>/rs`;
4. runs every case with both, from inside the library directory, and compares
   stdout, stderr and exit status, with each tool's own temp root replaced by
   `<ROOT>`;
5. then the migration phase (`migrate:` cases): beets-rs' `migrate-beets
   copies reference beets' `library.db` (with `--beets-config`) into a third
   library (`migrated/`, whose `directory:` is reference beets' library, so
   it points at the same files); `migrate:migrate-beets` checks it succeeds
   with no warnings, `migrate:read-only` that the beets database's bytes,
   mtime and directory are unchanged, and every `ls`, `mv`, `stats` and
   `fields` case runs again on the migrated library, compared with reference
   beets' output on its own library (`migrate:<case>`; a case's expected
   difference applies to its `migrate:` twin);
6. then the tag round trips (`tags:` cases): each tool runs `write` (and
   `write -f` with `id3v23: yes`), every file in the two libraries is read
   with MediaFile (the reference venv's) and compared field by field (an
   empty value and a missing tag count as the same, as beets stores them),
   and both tools import the files reference beets wrote into fresh
   libraries and list every tag field.
7. then the import phase (`import:` cases, `importphase.py`): a fake
   MusicBrainz in this process, one per tool run, bound to 127.0.0.1 on a
   free port, serves the releases in `tests/fixtures/mb` (a release search
   returns those sharing a word with its `release:(...)` term; recording
   searches match by title). Each case imports a fresh copy of generated
   audio with both tools (`IMPORT_CORPUS`, `IMPORT_CASES` in `cases.py`: `-t`
   with the match options, `-q`, `-s`, `-A`, aborting, "Group albums",
   "Rescan directory", and the metadata cases: VA, multi-artist credits,
   titled discs, works, and the options that shape applied metadata), with
   the case's config merged over the base one, answering each prompt as it
   appears; an answer can instead change the music directory first (for the
   rescan cases). Compared: the import's exit status, stdout and stderr
   (`import:<case>`), `ls` of the resulting items and albums
   (`import:<case>:ls`), every stored field of every item and album, one
   line per field, read from `library.db` (`import:<case>:db`), and the
   MusicBrainz requests made, with their parameters: search queries, limits
   and includes (`import:<case>:requests`).

The MusicBrainz fixtures 3333... and 4444... are generated by
`mbfixtures.py`. `mbexpected.py` (run with the reference venv and a
throwaway `BEETSDIR`) writes what reference beets parses from each fixture
and applies under a few configs to `tests/fixtures/mb/expected/`, which
beets-rs' unit tests compare against.

The report lists each case that isn't a plain PASS (`--show-pass` for all):
`DIFF` (with both outputs, or a unified diff when long), `EXPECTED` (a known
difference: the reason is printed) and `FIXED?` (listed as expected but now
equal: remove it from the list). The exit status is 1 if anything is `DIFF`
or `FIXED?`.

Cases, corpus, config and the expected differences live in `cases.py`:
queries (run with `ls` and `ls -a`) from beets' `test_query.py`,
`test_queryparse.py`, `test_datequery.py` and `test_sort.py`; templates
(`ls -f`, `ls -a -f`) from `test_functemplate.py` and `test_library.py`; path
formats and path options (`mv -p -d`). Relative date cases only use ranges that
are robust to when the run happens.

Options: `--only SUBSTR` (repeatable) runs matching case ids, `--keep` keeps
the temp dir, `-j N` sets parallelism, `-v` lists the setup steps.
